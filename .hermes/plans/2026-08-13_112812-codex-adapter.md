# Codex Skills-Only Adapter Implementation Plan

> **For Hermes:** Use `subagent-driven-development` only if this plan is approved for execution; keep the work in an isolated `hermes/*` worktree.

**Goal:** Package the existing canonical `skills/` directory as a skills-only Codex plugin without duplicating skill bodies or weakening the existing Claude Code and Hermes contracts.

**Architecture:** Add a minimal Codex plugin manifest that points at the repository’s existing `./skills/` directory, plus a repository marketplace entry that points at the same repository root. Keep the current `.claude-plugin/` package unchanged. Do not port the Claude-only UX agent into the Codex plugin: OpenAI’s migration guidance requires reusable agent behavior to become skills, and this adapter’s approved scope is existing skills only.

**Tech Stack:** Existing Python standard-library validator and `unittest` suite; Codex CLI 0.147.0; JSON manifests; no new dependencies.

## Completion contract

- **Outcome:** Codex discovers and installs a skills-only `agentic-woocommerce-toolkit` plugin that exposes the existing three WooCommerce skills from the one canonical `skills/` tree.
- **Verification:** Repository validator and full tests pass; manifest and marketplace contracts are tested; a disposable Codex configuration proves marketplace discovery, install, and fresh-session skill availability; the copied-cache plugin’s `skills/` entries resolve to the original expected `SKILL.md` contents.
- **Constraints:** No duplicated `SKILL.md`, MCP server, hooks, UI, credentials, agent conversion, scheduler, external marketplace submission, tag, release, or repository settings change. Preserve all Claude and Hermes behavior.
- **Stop/ask:** Stop for Andrew before adding an MCP, hook, agent-derived skill, public marketplace submission, tag, release, or any required Codex behavior that cannot be proven with a disposable local configuration.

## Risks and decisions

- **Codex CLI schema may differ from the current public documentation.** Resolve with local CLI `--help` and a disposable marketplace probe before locking the manifest contract.
- **A Codex plugin package does not carry Claude’s UX-agent semantics.** Keep the UX reviewer Claude-only; do not create a new skill just to preserve parity.
- **Public submission requires identity/review and is not included.** The implementation ends at local Codex acceptance plus PR readiness.
- **No measured Codex use case after acceptance:** keep the adapter documented but do not expand it with MCP, hooks, UI, or automation.
